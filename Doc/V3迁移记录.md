## 2. `.ioc` 改动（`G474 V3.0.ioc`，CubeMX 6.18.1）

- 新增 `NVIC.EXTI1_IRQn / EXTI9_5_IRQn / EXTI15_10_IRQn`（抢占 5，使能）——原来只配了 EXTI 引脚、没开 NVIC。
- `SPI1/SPI2.BaudRatePrescaler` 16 → **32**（10.625MHz → 5.3MHz，两颗传感器上限都是 10MHz）。
- **`SPI2.CLKPolarity/CLKPhase` 显式设为 High / 2Edge（SPI Mode 3）**——BMI088 只支持 Mode 3；
  `.ioc` 不写这两项时 CubeMX 用默认 Mode 0（V1 的 QMI8658A 支持 Mode 0），此时 BMI088 芯片 ID 读不回来
  → `BMI088.Ready=0` → 陀螺/加计/温度全 0 → 加热恒 `NO_SENSOR`、零漂标定 `GIVEUP`、无法解锁。
  SPI1（BMP581）保持 Mode 0 即可（BMP581 支持 mode 0/3）。
- `TIM2_CH1~4` 的 DMA：`WORD` → **HALFWORD**，`LOW` → **HIGH**（DShot 的 CCR 缓冲是 uint16_t）。
- 重新生成命令：
  ```
  STM32CubeMX.exe -q script.txt
  # script.txt:
  config load "<abs>\G474 V3.0.ioc"
  project generate
  exit
  ```

**CubeMX 重新生成后必须手工恢复两处**（否则编译不过/链接不到 DSP）：
1. `Middlewares/Third_Party/FreeRTOS/Source/portable/RVDS/ARM_CM4F/port.c`、`portmacro.h`
   → CubeMX 会覆盖成 ARMCC5 版（`__forceinline`/`__asm{}`），AC6 编不过。仓库 HEAD 里是 GCC/AC6 可用版本。
2. `MDK-ARM/G474 V3.0.uvprojx` 里 CMSIS-DSP 组件的 `<targetInfo name="G474 V1.0"/>` → `G474 V3.0`（否则找不到 `arm_math.h`）。
   另外 include path 里的 `../USB_Device/*`、`../Middlewares/ST/*`、`../Drivers/BSP/Components/vl53l1cb` 要清掉。

## 4. 加热恒温设计（重点）

### 控制
- 目标 40℃，20ms 一个窗口；`Heater_Update()` 由 Sensor 任务每 ~20ms 调用。
- 前馈 20% + PI（Kp=25%/℃、Ki=0.5%/(℃·s)），抗积分饱和 + 占空比斜率限制（每窗口 ≤10%）。
- 温度源：**BMI088 片内温度**（就是被加热的器件）；`BMI088.Temp_Tick` 每次更新打时间戳。
- 输出：TIM4 `OPM` 单脉冲，宽度 = 占空比×20ms，到 ARR 硬件自动停 CEN。
  **软件卡死最多再加热 20ms**，不存在“一直加热”。

### 保护（任一成立立刻拉低 PWM）
1. 温度无效：`BMI088.Ready=0` / `Temp_Tick` 超 100ms 未更新 / 非有限值 / 超 −40~85℃ → 关（自动恢复）。
2. 过温 **≥46℃** → 关并**锁存**（`Heater_ClearFault()` 且温度 <40℃ 才能清）。
3. **≥41℃** 不加热；**>40.3℃** 死区不加热（防在目标点反复打）。
4. 满功率(≥80%)连续 180s 温度涨不到 1℃ → 判传感器卡死/加热丝断 → 锁存 `NO_RESPONSE`。
5. `Error_Handler`、NMI、HardFault、MemManage、BusFault、UsageFault **第一条语句** `Heater_EmergencyOff()`。
6. 上电最早时刻（`main()` SysInit）就把 PA11 拉低，早于 GPIO/TIM 初始化；栅极另有 10k 下拉。
7. 关断顺序：先 `CCR1=0` 让输出立刻无效，再停计数器。
8. 故障锁存后 `Heater_Update()` 每拍先判故障并关；`HEATER_FAULT_EMERGENCY` 不允许清除。

### 可调参数（**全部在 `User/Task/Parameter.h` 第 6 节**）
`HEATER_TARGET_C / HEATER_SOFT_STOP_C / HEATER_TRIP_C / HEATER_FF_DUTY / HEATER_KP / HEATER_KI /
HEATER_DUTY_MAX / HEATER_DUTY_SLEW / HEATER_DEADBAND_C / HEATER_NO_RESPONSE_*`。

### 调试量（结构体 `Heater`）
`Target_C、Temp_C、Duty、Integral、Window_Count、Fault_Count、Fault`
- `Window_Count` 持续增加 = 程序在跑；
- `Duty` 长期 100% 且 `Temp_C` 上不去 = 0.2W 功率不够（正常饱和，不是死机）。

## 6. 已知风险 / 待确认

1. **IMU 安装方向未标定**：`IMU_Cal_Fixed_Frame_R` 是单位阵，输出=BMI088 芯片坐标系。
   首飞前必须核对 Roll/Pitch 方向，或临时 `IMU_Cal()` 六面标定后把参数填回。**否则自稳可能反向。**
2. **高度环要重调**：原来按 TOF（5mm 噪声）调的增益，现在喂气压计；定点模式没有光流速度，会退化成“保持姿态”。
3. ~~**USART1 波特率不一致**：`.ioc` 是 115200，`Vofa` 代码注释/节奏按 4Mbps 设计（未改）。~~
   **已改**：USART1 = **4 Mbaud**（`.ioc` + `usart.c` 同步），VOFA 发送 = **1 kHz**（`Vofa.h` 的 `VOFA_SEND_HZ = 1000`，TIM7 由 `Vofa_Set_Send_Hz()` 自动算 PSC/ARR）。
   注意 PCLK2 = 170 MHz 除不出整数分频，实际波特率 ≈ **4.048 Mbaud（+1.19%）**，主机端按 4 M 设置即可（在 UART 容差内）。
   实测：`Vofa_Tick_Count` 与 `Vofa_Send_Count` 同步增长 11867 帧 / 11.866 s = **1000.08 Hz**，`Vofa_Drop_Count = 0`；
   当前 6 通道 → 28 字节/帧，占用约 7% 带宽（4.048 M 下每帧约 69 µs）。
4. **加热功率只有 ~0.2W**：从室温升到 40℃ 可能很慢甚至到不了，届时会长期 100%（属正常，不是卡死）。
   `NO_RESPONSE` 只在“完全不升温”时动作。
5. **加热 50Hz 可能有板子啸叫**：如果听到的是板子而不是蜂鸣器的声音，可把窗口频率提到 ≥1kHz（需保留 OPM 触发机制）。
6. **蜂鸣器“卡住”问题**：已修 ADC 采集 + 告警重触发（原因见下），待用户确认现象是否消失。
   - 旧代码每 20ms 重设 `Buzzer_SoundEffect_Aim_ON`，`Buzzer_Task` 会永远停在第一个音上；
   - `HAL_ADC_Start()` 后立刻 `HAL_ADC_GetValue()`（没等 EOC、没 Stop），BatV 可能是无效值，落在 5~7V 就一直报警。
7. 输出名仍是 `G474 V1.0`（未改，避免影响烧录/ELF 路径）。
8. **所有改动未 commit**（`git status` 166 项，含用户之前的删除）。

## 9. 上机调试记录（2026-10-29，用 EmberProbe 在线调试）

首轮上机时现象：`Heater.Window_Count=0`、`Fault=NO_SENSOR`、`INS.Accel/Gyro` 恒 0、零漂标定 GIVEUP。
按下面顺序逐个定位并修复，现全部通过。

### 9.1 已修复的软件问题

| # | 问题 | 修复 |
|---|---|---|
| 1 | **SPI2 是 Mode 0，BMI088 只支持 Mode 3** | `spi.c` 的 `hspi2` 改 `CLKPolarity=HIGH / CLKPhase=2EDGE`；`.ioc` 同步写死这两项 |
| 2 | **`BMP581_Init()` / `BMI088_Init()` 只在启动瞬间读一次芯片 ID**，读不到就永久 `Ready=0`，之后再也不重试 | 新增 `BMP581_Wait_Chip_ID()` / `BMI088_Acc_Wait_ID()` / `BMI088_Gyro_Wait_ID()`，各重试 50 次 × 5 ms |
| 3 | **BMP581 INT 只触发 1 次**（`Int_Count` 恒 1，全靠 100 ms 兜底轮询） | `INT_CONFIG` 由 `0x08`（锁存）改 `0x09`（脉冲）；并在 `BMP581_Read_Data()` 末尾读一次 `INT_STATUS(0x27)` 释放标志。修好前 48 Hz 数据靠轮询，修好后 `Int_Count == Sample_Count`、`Poll_Count == 0` |
| 4 | **禁止在 Sensor 任务里对 SPI2 发裸读**（调试时踩到）：SPI2 由 Flight 任务(2 kHz, 更高优先级)独占，Sensor 任务插一脚会打断传输，表现为温度/加速度偶发读到 0 | `Sensor.c` 的 `Sensor_Diag_Snapshot()` 只允许**拷贝已存字段**，不得发 SPI |

### 9.2 已定位的硬件问题

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | 板子发烫（BMI088 77℃、BMP581 65℃），但软件侧 `Window_Count=0`、`PA11` 实测 0 V、`TIM4.CCR1=0`、`CEN=0` | **Q1（AO3400，SOT-23）D-S 击穿**，加热丝 5 V 常通，与 PA11 无关 | 换 Q1 后温度立刻回到 32~35℃，加热闭环恢复 |
| 2 | BMI088 曾完全无应答（两颗 die Chip ID 都是 0/255） | **加速度计虚焊** | 补焊后 Chip ID = 0x1E / 0x0F |
| 3 | 网表里 **U34 pin7 `PS` 接 GND** | BMI088 的 PS 是加速度计协议选择（0=I²C, 1=SPI）。当前 SPI 能通说明实板/手册理解还需复核，**若后续再出现加速度计无应答，第一时间量 PS 脚** | 待确认 |

| 6. 加热 | `HEATER_*`（目标温度、保护阈值、PI、无响应保护） | `Heater.c` |
| 7. 通信 | `VOFA_SEND_HZ` / `VOFA_CH_MAX` | `Vofa.h` |

使用注意：

- `Parameter.h` **只放数值和开关**，不放类型/结构体/函数；
- Roll/Pitch 目前共用 `CTRL_ANGLE_RP_*` / `CTRL_RATE_RP_*`（两个轴参数原本就一样）；
  若以后机架不对称需要单独调，再拆成 ROLL / PITCH 两组即可；
- 改量程时要同步改驱动里的寄存器常量（如 `BMI088_ACCEL_RANGE_G` ↔ `ACC_RANGE` 寄存器值）；
- `FLIGHT_LOOP_HZ` 改了要同步改 `tim.c` 里 TIM6 的 PSC/ARR，两者必须一致；
- `VOFA_SEND_HZ` 只影响 TIM7 节拍，`Vofa_Set_Send_Hz()` 会自动算分频，无需动 `tim.c`。
